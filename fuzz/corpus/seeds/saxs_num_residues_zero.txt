# Root cause: when NumResidues=0 (and NumRNA=NumDNA=NumCarb=0), total_mass=0, so
# molarity = ProteinConc / 0 = Infinity, and num_monomers overflows.
# Both Java and Rust saturate to i32::MAX / Integer.MAX_VALUE = 2147483647,
# so atom counts are the same, but the elastic (coherent) scattering coefficient
# diverges ~10.5% between the two implementations due to floating-point behaviour
# at these extreme atom counts during density/solvent-water calculation.
# This produces ~5.4% Dose Inefficiency and ~10.5% Diffraction Efficiency divergence.
# Not easily fixable without exactly matching Java's FP evaluation path.
